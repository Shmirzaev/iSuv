# iSuv UX follow-up suggestions

These proposals intentionally remain outside the operator-shell redesign. Each changes product behavior, data contracts, or operational workflow and therefore needs separate discovery, authorization, and acceptance work.

| Opportunity | Problem | Proposal | Estimated effort |
| --- | --- | --- | --- |
| Real geographic base map for Map & Network | The current deterministic synthetic SVG is useful for topology and testability but cannot provide authoritative geographic context, roads, settlements, or official boundaries. | Add a replaceable OGC-compatible tile/vector adapter, official geometry import, attribution, offline/degraded behavior, and a security/data-sovereignty review. Preserve the topology view as a coordinated operational layer. | Large (6–10 weeks plus official data/provider decisions) |
| Saved filter presets and shareable views | Operators must recreate complex territory, station, quality, alarm, and audit filters for each shift or investigation. | Store named personal/team presets and encode an authorized, versioned subset in shareable URLs. Revalidate every preset against the current user's server-side territory scope when opened. | Medium (3–5 weeks) |
| Alarm bulk actions | High-volume events require repetitive acknowledgement and assignment, increasing response time and errors. | Add multi-select acknowledge/assign actions with per-record capability evaluation, one required reason, partial-failure reporting, idempotency, and an immutable audit entry for every affected record. Do not add automatic clearing. | Large (5–8 weeks) |
| Report snapshot diffing | Immutable snapshots are reproducible, but reviewers cannot quickly understand what changed between two versions or data cutoffs. | Add a typed snapshot comparison view for values, source revisions, methodology, quality coverage, approvals, and generated artifacts. Highlight added/removed evidence without rewriting either report. | Medium–large (4–7 weeks) |
| Per-territory operator home page | The national dashboard gives broad awareness but district and basin operators need a shift-specific starting point. | Compose a server-authorized home page from assigned territory, unresolved incidents, stale/unreliable stations, plan variance, handover notes, and watched assets. Keep the national dashboard available to authorized roles. | Large (6–9 weeks) |
| Station watchlists and notifications | Operators cannot currently follow a small set of important stations or learn when their condition changes without repeatedly filtering. | Add personal/team watchlists and an event-subscription model for data loss, quality change, alarm lifecycle, and threshold proximity. Delivery channels, quiet hours, escalation, and legal policy require separate governance; start with an in-app inbox. | Large (6–10 weeks) |
| CSV export for data tables | Users cannot take bounded live, alarm, analytics, report, or audit result sets into approved downstream analysis workflows. | Add server-generated, territory-authorized CSV exports with locale-neutral machine values, explicit units, UTC timestamps, filter/cutoff metadata, synthetic classification, row limits, audit logging, and formula-injection protection. | Medium (3–5 weeks) |
| Shift handover log | Incident timelines do not capture broader operational context between dispatcher shifts. | Add an append-only, territory-scoped handover record with acknowledged receipt, watched conditions, unresolved questions, linked alarms/incidents/stations, and audit history. | Medium–large (4–7 weeks) |
| Cross-workspace investigation bundle | Moving between map, live telemetry, alarms, analytics, reports, and audit loses the investigation context. | Introduce a read-only investigation workspace that pins a time window and authorized asset set, then deep-links coordinated evidence from each subsystem. Persisting bundles should be versioned and auditable. | Large (6–9 weeks) |
| Table density and personal column preferences | The Essential/expanded column pattern reduces overflow, but different roles need different persistent data density. | Add per-user column order, density, and visibility preferences with a safe reset. Keep mandatory safety/status columns non-hideable and do not let preferences change API authorization. | Small–medium (2–4 weeks) |
| Mobile/offline field inspection | The responsive console is not a field data-capture workflow and cannot safely collect evidence during connectivity loss. | Build a separate offline-first inspection surface for QR/device identification, calibration tasks, photos, GPS evidence, signed synchronization, and conflict handling. | Extra large (10–16 weeks plus device/security validation) |
| Accessible chart data export | Visually hidden chart tables support screen readers but cannot be independently copied or downloaded. | Add a visible “View chart data” disclosure and bounded accessible CSV for each analytical chart, including denominator, exclusions, cutoff, method version, and provenance. | Small (1–2 weeks) |

Effort ranges assume one cross-functional product squad and exclude procurement, official GIS/hydrological inputs, government security accreditation, and production infrastructure work.
